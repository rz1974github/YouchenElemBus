# 松山車站 ↔ 玉成國小 公車動態

## 目標
手機可用的 2D 公車動態畫面，只接 TDX 即時 API，不存歷史、不做帳號、不做報表。

## 用語（重要）
本 App 只有兩個方向，一律稱為 **上班 / 下班**：

| App 用語 | 程式代號 | 行駛方向 | 上車站 |
|---|---|---|---|
| 上班 | `toWork` | 松山車站 → 玉成國小 | 玉成里 |
| 下班 | `toHome` | 玉成國小 → 松山車站 | 西新里 |

**不要使用「去程 / 回程 / 順向 / 逆向 / outbound / inbound / direction」描述本 App 的方向。**
這些詞是 TDX 的用語：TDX 的 `Direction`（0/1）是「每條路線自己」的去返程，13 條路線各自不同，
和上班 / 下班沒有固定對應（實測：205 的 0 是下班、306 的 0 是上班）。程式只把 TDX `Direction` 當成分組鍵，
上班或下班由 TDX `StopOfRoute` API 的站序判斷。

## 顯示規則（唯一一條）
**距上車站 `thresholdMinutes` 分鐘內，而且還沒過上車站的車，才顯示。**

- 過了上車站之後，TDX 在上車站回報的是下一台車，這台車就不再顯示。
- 不另外加任何依站點、車號、時間的特例。

## 畫面
- 抽象等距路線圖（SVG），站名在左；松山車站固定在下方、玉成國小固定在上方。
- 上班時車子由下往上，下班時由上往下。
- 每台符合條件的車佔右側一條平行線；車道在更新之間保持不變，新車補最小的空車道。
- 每站同水平位置顯示該車到站分鐘數。
- 車子位置：
  - ETA = 0：貼在該站上。
  - 行駛中：放在前一站與下一站正中間。
  - 下一站是首站：放在首站外側半個站距。

## 設定（`src/data/appsettings.json`）
- `thresholdMinutes`：顯示門檻（分鐘）
- `pollingIntervalSeconds`：更新頻率（秒）
- `busNumbers`：要查詢的路線
- `stationNames`：依上班方向排列的站名，只存一份；下班反序讀取
- `trips.toWork` / `trips.toHome`：顯示名稱與上車站
